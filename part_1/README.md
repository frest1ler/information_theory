# Первая часть курса: теория информации

В каталоге находится исследовательская работа:

- [`huffman_optimal_block_size.ipynb`](huffman_optimal_block_size.ipynb) — исследование влияния размера блока на среднюю длину и избыточность кода Хаффмана при точно известных вероятностях.

## Краткая логика работы

Для каждого источника строятся точные распределения блоков длины (m=1,2,3,4). Средняя длина блока пересчитывается на один исходный символ и сравнивается с энтропией. Практический размер блока выбирается как минимальный (m), который уступает лучшему исследованному результату не более чем на (arepsilon=0.01) бит/символ.

## Пояснения к графикам для защиты

### 1. Абсолютная избыточность фиксированных источников

- По вертикали показано (R_m=\ell_m-H), то есть расстояние средней длины до энтропии.
- У равномерного и двоично-рационального источников (R_m=0): их вероятности уже согласованы с целыми двоичными длинами.
- Для остальных источников блокирование обычно уменьшает избыточность.
- Фактическая последовательность (R_m) не обязана строго убывать, хотя верхняя граница (1/m) уменьшается.

### 2. Экспоненциальный рост блочного алфавита

- Число возможных блоков равно (M^m).
- При увеличении (m) на единицу число блоков умножается на (M): в 4 раза для (M=4) и в 5 раз для (M=5).
- Прямые имеют разные наклоны из-за логарифмической шкалы: (\log(M^m)=m\log M).
- График показывает цену небольшого выигрыша в длине кода: для (M=4,m=4) уже требуется 256 блоков, для (M=5) — 625.

### 3. Избыточность двоичного семейства

- Исследуется (P(p)=(p,1-p)), а график показывает (R_m(p)=\ell_m(p)-H(p)).
- При (p=0.5) источник равномерный и избыточность равна нулю.
- При (m=1) код всегда использует один бит, поэтому (R_1(p)=1-H(p)) растёт с концентрацией источника.
- Изломы возникают при перестройке дерева Хаффмана, а пересечения кривых показывают, что (m+1) не всегда лучше (m) в каждой точке.

### 4. Средняя длина и энтропия двоичного семейства

- Чёрная пунктирная линия — энтропия (H(p)), остальные линии — (\ell_m(p)).
- Вертикальное расстояние между (\ell_m) и (H) равно избыточности.
- При росте (p) энтропия падает, но посимвольный код остаётся на уровне одного бита.
- Блочные коды лучше следуют за энтропией, особенно для сильно концентрированного источника.

### 5. Избыточность четырёхсимвольного семейства

- При (a=0.25) распределение равномерное, поэтому двухбитный код точен и (R_m=0).
- С увеличением (a) источник становится более концентрированным.
- Избыточность меняется немонотонно из-за дискретных перестроек дерева.
- Большие блоки обычно помогают, но пересечения линий снова показывают отсутствие гарантии улучшения при каждом переходе (m\to m+1).

### 6. Практический выбор размера блока

- Для каждой точки сначала находится (\ell_{\min}), затем выбирается минимальный (m), для которого (\ell_m\leq\ell_{\min}+0.01).
- (m_\varepsilon^*=1) означает, что больший блок экономит не более 0.01 бит/символ.
- (m_\varepsilon^*=4) означает, что только максимальный исследованный блок укладывается в допуск.
- Выбранный блок не обязательно даёт абсолютный минимум: критерий предпочитает меньшую сложность при почти одинаковой длине.
- Ступени появляются из-за дискретного выбора (m\in\{1,2,3,4\}).

### 7. Экспериментальная проверка границы

- Для каждого (m) берётся максимальная избыточность по всем исследованным распределениям.
- Сплошная линия показывает этот максимум, пунктирная — универсальную границу (1/m).
- Сплошная линия должна находиться ниже пунктирной — это и есть проверяемое соотношение.
- Это численная проверка на выбранной сетке распределений, а не доказательство теоремы.
- Распределение, на котором достигается наблюдаемый максимум, может быть разным для разных (m).

## Ограничения интерпретации

Рассматриваются IID-источники с точно известными вероятностями, двоичный код Хаффмана и только (m=1,2,3,4). Число (M^m) служит показателем роста сложности, но не точной оценкой памяти. Формат хранения дерева и служебные данные файла не учитываются.
